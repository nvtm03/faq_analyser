# FAQ Analyser

Локальный поиск кандидатов на неполные дубли FAQ. Основной файл — `faq_partial_duplicates.ipynb`.

## Запуск

1. Используйте Python 3.10 или новее и установите зависимости из `requirements.txt` в окружение для ноутбука.
2. Укажите пути к своим Excel-выгрузкам в `EXPORT_FILES` в первой ячейке. Поддерживаются лист «Выгрузка» и поля, которые проверяет функция `read_records`. CSV с разметкой `BENCHMARK_FILE` можно подключить при наличии.
3. Запустите все ячейки. В `results/partial_run/` появятся HTML с поиском и фильтрами и Excel для вычитки. Файлы с реальными вопросами и ответами храните в рабочем контуре.

## Откуда берётся HTML

Ноутбук читает активные карточки ЕЛЧ, считает cosine TF-IDF по вопросам и ответам, проверяет вложенность текста, различия в операциях и условиях. Он формирует списки пар для приоритетной вычитки, сверки контекста и исключённых по существенным различиям. Функция `write_html` подставляет результаты в таблицы уже после прогона. Полные совпадения открываются отдельной вкладкой. `write_workbook` сохраняет те же очереди и результаты сравнения правил в Excel.

В базовом правиле пороги cosine ответа и вопроса составляют 0,76 и 0,46. Порог взвешенного покрытия для вложенности — 0,93. Правила также учитывают общую формулировку вопроса и длинное текстовое вложение. Настройки вынесены в первую ячейку. Межпродуктовые пары остаются доступны для сверки. `ONLY_SAME_PRODUCT = True` ограничивает выдачу одним продуктом.

## Проверенный результат

На одном рабочем снимке из 9 231 активной карточки получили 188 приоритетных пар и 679 пар для сверки контекста. На проверочной выборке из 95 размеченных пар один порог cosine ответа оставил 50 пар. Дополнительные признаки сократили очередь до 15, сохранив те же 7 из 14 полезных пар. Это результат на выборке. Полноту поиска по базе и влияние на top-3 нужно оценивать на поисковых запросах.

## Режим с эмбеддингами E5

Для прогона с E5 укажите готовый полный массив `E5_NPY` и соответствующий ему локальный снимок `E5_SNAPSHOT`. С включённым `E5_NEIGHBOUR_FLOOR` ноутбук добавит кандидатов из поиска по векторам. На листе «Пороги E5» можно сравнить варианты на размеченных парах, у которых найдены оба вектора. `E5_MIN_COSINE` включает выбранный порог в правила отбора. Приведённые выше числа получены в резервном режиме TF-IDF. На рабочем кэше E5 пороги и качество ещё предстоит проверить.

Результат — очередь для редактора. Решения об изменении базы принимает человек.
